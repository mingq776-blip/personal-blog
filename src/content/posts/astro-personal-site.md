个人网站很容易在“选择一个完美技术栈”上消耗太久。我的目标很明确：文章可以长期写，项目可以持续更新，动效足够有记忆点，但不牺牲阅读和加载速度。

最终选择的结构是：Astro 负责内容和静态页面，React 只负责局部交互，Three.js 负责首页粒子视觉。

## 为什么不是纯博客模板

模板可以快速上线，但个人网站通常同时承担三种功能：

- 用文章记录思考和过程；
- 用项目证明具体能力；
- 用视觉和个人故事建立识别度。

纯博客模板往往只优化第一种。Astro 的内容集合和组件体系，则可以让文章与项目共享同一套布局，又保留各自的数据结构。

## 内容与交互分开

页面大体分成两类：

1. 文章、归档、标签和关于页面，以 HTML 和 CSS 为主，不依赖客户端 JavaScript；
2. 首页 3D、主题切换、搜索结果等局部功能，按需加载 React 或 Pagefind。

这比把整个网站做成单页应用更简单，也更容易保证首屏速度。

## 3D 应该服务于内容

首页粒子会响应鼠标和滚动，但它不应该妨碍阅读。实现时保留了几个约束：

- 3D 区域不拦截页面滚动；
- 移动端主动减少粒子数量；
- 用户开启“减少动画”后降低运动幅度；
- 不支持 WebGL 时显示静态轨道背景；
- 正文和导航始终是可访问的 HTML。

酷炫效果可以成为入口，但内容必须始终是主角。

## 写作工作流

所有文章都使用统一的 Markdown 元数据：

```yaml
title: 文章标题
description: 文章摘要
pubDate: 2026-10-03
category: 技术
tags: [Astro, React]
featured: true
draft: false
```

写完文章、运行构建、推送 Git，托管平台自动发布。草稿不会进入生产环境，构建过程也会检查缺少的字段。

## 先完成，再优化

个人网站不需要一次完成所有功能。第一阶段只要做到：

- 文章能够稳定发布；
- 首页和项目页能表达个人风格；
- 手机与键盘访问正常；
- 构建和部署流程可重复；
- 数据随时可以备份和迁移。

先把内容循环跑通，再逐步增加评论、数据和更复杂的交互。一个持续更新的简单网站，胜过一套很久没有内容的完美系统。
